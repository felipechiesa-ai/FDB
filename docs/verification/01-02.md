# 01-02 verification

Status: `[COMPLETE]`. Records survive reopening, invalid relationships roll back, and empty-library creation is repeatable. Verified by automated tests on a real temporary SQLite file.

## Environment (2026-10-16)

- macOS 26.6.2 on Apple silicon, Xcode 27.0, Swift 6.4, GRDB.swift 7.11.1 (see `01-01.md`)

## Checks run

| Check | Command | Result |
| --- | --- | --- |
| Domain and persistence tests | `swift test --package-path Packages/FDBKit` | 29 tests passed: 16 domain, 13 persistence |

Persistence tests that cover this substage (`LibraryStoreTests`):

- `savedDataSurvivesReopeningTheFile`: a player saved to a file is read back after the database is reopened.
- `failedSaveLeavesNothingBehind`: a save that references an unknown country throws and leaves no player row (transaction rollback).
- `reversedMembershipDatesAreRefusedWithoutAWrite`: an invalid interval writes nothing.
- `seedsEveryIsoCountryOnce` and `countryIdsAreStableAcrossLibraries`: a new library is seeded with 249 sovereign countries, and the same country has the same ID in every library.
- The smoke test `foreignKeysAreEnforcedOnOpen` confirms foreign keys are enforced on every connection.

## Limitations

- The database uses the default rollback journal with one writer (`DatabaseQueue`). WAL is not configured yet.
- Migrations are `v1` (people, clubs, rosters) and `v2` (media, added with 01-06). The v1-to-v2 upgrade is tested on a version-one database file (`MigrationTests`), and the demo library created before v2 opened after the upgrade in the UI tests.
