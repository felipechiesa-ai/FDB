## Performance

Environment: macOS 26.6.2, Apple M4, 16 GB RAM. The library was on the internal disk, in the app container.

Command: `FDB_PERFORMANCE=1 swift test --package-path Packages/FDBKit --filter LibraryPerformanceTests`

Synthetic data: 10,000 players and 500 clubs. Same-name players are included on purpose.

| Measure | Result | Budget |
| --- | --- | --- |
| Player directory, first query after reopening the database | 40.9 ms | 200 ms |
| Player directory, warm median of 5 | 38.7 ms | 200 ms |
| Player search "garcia", warm median of 5 | 5.7 ms | 200 ms |
| Club directory, warm median of 5 | 2.0 ms | 200 ms |
| Save an existing player, median of 20 | 0.5 ms | 500 ms |

Seeding took 1624.6 ms. That is not a budget.

What these numbers do not cover:

- A true cold start. The file had just been written, so the operating system's cache was warm. A run with a purged cache is not measured yet.
- The external SanDisk volume the project lives on. The library ran on the internal disk.
- The UI. The directory query returns all 10,000 rows. Scrolling and drawing them is not measured.
- Saves that change a photo. The budget excludes image decoding, and the measured saves do not change photos.
